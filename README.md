# Практическая работа № 2 — вариант 8

Дисциплина: «Конфигурационное управление».

## Текущий этап

Этап 2: сбор данных о прямых зависимостях выбранной версии npm-пакета.
Метаданные загружаются по HTTP(S) и разбираются собственным кодом.
Готовые менеджеры пакетов и библиотеки анализа зависимостей не используются.

## Запуск в браузере

Если загружена папка .github, проверки доступны в Actions → Check project.
Они запускаются после коммита и через Run workflow.
Actions — дополнительное удобство, а не часть алгоритма программы.
Проверки выполняются также локально командами ниже.

## Требования и сборка

Python 3.10+, Bash для run.sh. Используется стандартная библиотека.
Сборка, npm install, Node.js и Graphviz на этом этапе не нужны.
Для настоящего запроса нужен интернет. Тесты работают без интернета.
Все команды выполняются из корня проекта.

```bash
bash run.sh --help
bash run.sh --package is-odd --repository https://registry.npmjs.org \
  --version 3.0.1
```

Ожидаемое требование is-odd@3.0.1:

```text
is-number: ^6.0.0
```

Пакет без прямых зависимостей:

```bash
bash run.sh --package is-number --repository https://registry.npmjs.org \
  --version 6.0.0
```

Ожидается (нет прямых зависимостей).
Также поддерживается python -m src.main с теми же аргументами.

## Семь параметров

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| --package | Имя пакета npm | Обязательный |
| --repository | HTTP(S) URL реестра | Обязательный |
| --test | Переключатель тестового репозитория | Выключен |
| --version | Точная версия SemVer | Обязательный |
| --output | Путь будущего SVG | graph.svg |
| --ascii | Переключатель будущего ASCII-дерева | Выключен |
| --filter | Подстрока для будущего исключения пакетов | Пустая строка |

Флаги --test и --ascii передаются без значений.
Поддерживается структура имён @scope/package и длина до 214 символов.
В тестовом режиме имя состоит из A-Z, указанный файл должен существовать.
Анализ тестового графа появится на этапе 3: пока --test даёт пояснение.
Версия начального пакета задаётся точно, например 3.0.1 или 1.0.0-beta.1.
latest и диапазоны вроде ^3.0.0 в --version не принимаются.
Путь SVG должен иметь расширение .svg и существующую родительскую папку.
Фильтр регистрозависимый, не должен исключать начальный пакет.
Пустой фильтр отключён. Пробельные и управляющие строки отклоняются.
На этапе 2 фильтрация, SVG и ASCII-дерево ещё не выполняются.

## Получение данных

Для выбранных имени и версии формируется URL вида:

```text
https://registry.npmjs.org/is-odd/3.0.1
```

Имя с областью и версия кодируются как части URL.
Поле dependencies разбирается стандартным json.
Проверяется совпадение имени и версии в ответе с запросом.
Таймаут HTTP — 30 секунд. Ошибки сети, HTTP, JSON и структуры ответа
обрабатываются понятным сообщением без traceback.

На этом этапе читаются обычные зависимости поля dependencies.
devDependencies, peerDependencies и optionalDependencies отдельно
не включаются. Диапазоны требований сохраняются в исходном виде;
подбор версий транзитивных зависимостей появится вместе с графом.

## Функции

### src/main.py

- build_parser() — семь параметров и справка.
- validate_package(args) — структура и длина имени.
- validate_registry_url(address) — схема, хост и пробелы URL.
- validate_url_details(url) — лишние части URL и порт.
- validate_repository(args) — выбор проверки URL или файла.
- validate_version(args) — точная версия SemVer.
- validate_output(args) — расширение и папка SVG.
- validate_filter(args) — допустимость подстроки.
- arguments(argv=None) — чтение и проверка настроек.
- main(argv=None) — получение и вывод прямых зависимостей.

argv=None означает чтение командной строки; тесты передают список.

### src/registry.py

- metadata_url(repository, package, version) — адрес запроса.
- fetch_metadata(package, version, repository) — загрузка JSON.
- validate_dependencies(dependencies) — проверка требований.
- validate_metadata(metadata, package, version) — проверка ответа.
- direct_dependencies(package, version, repository) — прямые зависимости.

## Структура

- src/ — код программы.
- tests/test_cli.py — 16 проверок параметров.
- tests/test_registry.py — 10 проверок второго этапа.
- tests/fixtures/chain.json — данные для будущего тестового графа.
- tests/demo_cli.py — офлайн-демонстрация с явно подменённым HTTP.
- tests/check_style.py — размеры строк, функций, файлов, аргументов,
  наличие docstring у функций.

- .github/workflows/check.yml — необязательные проверки на GitHub Actions.
- .gitignore — исключения для служебных и генерируемых файлов.

## Проверки

```bash
bash run.sh --tests
python tests/demo_cli.py
python tests/check_style.py
```

Всего 26 тестов. Ответы сервера в тестах подменяются, npm не вызывается.
Для реальной демонстрации используйте команды is-odd и is-number выше.

Коды завершения: 0 — успех; 1 — ошибка выполнения; 2 — ошибка CLI.
